# GapLens: запуск и работа

GapLens восстанавливает пропуски во временном ряду по похожим историческим фрагментам. Результат — CSV, JSON с объяснением и интерактивный HTML. Нужны наблюдения с обеих сторон пропуска: это инструмент для ретроспективного анализа.

## Windows: точные команды

Установите Python 3.12 с официального python.org. Откройте PowerShell в папке проекта, где находятся `pyproject.toml` и `README.md`. На этапе установки зависимостей нужен Интернет; данные уже включены в проект. GPU не используется.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\gaplens.exe repair --reference examples/reference.csv --input examples/with_gaps.csv --output my-repair --require-complete
Invoke-Item .\my-repair\report.html
```

Активация окружения не нужна, поэтому менять PowerShell ExecutionPolicy не требуется. Если `my-repair` уже существует, укажите новую папку либо осознанно добавьте `--overwrite`. Эта опция заменяет только `repaired.csv`, `report.json`, `report.html`; входные файлы защищены.

Установка, полный эксперимент, CLI и экспорт проверены на Linux x86-64 с Python 3.12.14. [GitHub Actions для v2](https://github.com/dreamybu3/propro/actions/runs/39853118660) успешно выполнил тесты, проверку сохранённых результатов и обе демонстрации на Ubuntu и Windows с Python 3.12. Подробности — в [отчёте о проверках](v2/VALIDATION.md). Измерения времени и памяти относятся к облачной машине; производительность на конкретном ноутбуке может отличаться.

## Что посмотреть

В демонстрации скрыты 42 известных значения реального пассажиропотока NYC. Ожидаемый итог: восстановлены 3 из 3 пропусков, сохранены все 2 022 исходных наблюдения. В HTML выберите пропуск, проверьте кривую, интервал и список исторических соседей. CSV содержит исходные значения, оценки и статусы; JSON — параметры, контрольные суммы и калибровку.

Готовый отчёт v2 сохранён в `results/v2/demo/report.html`; новая команда создаёт отчёт текущего кода в `my-repair`. Для просмотра не нужен сервер. `examples/ground_truth.csv` — отдельная истинная последовательность для проверки демонстрации; алгоритм её не читает. Исходный отчёт v1 остаётся в `results/demo/report.html` как часть воспроизводимого первого исследования.

## Проверки и воспроизведение v2

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/run_experiments_v2.py --config configs/benchmark_v2.json --plan results/v2/masks.json --output results/my-v2-reproduction
.\.venv\Scripts\python.exe scripts/summarize_v2.py --input results/my-v2-reproduction --output results/my-v2-summary
.\.venv\Scripts\python.exe scripts/verify_v2.py --input results/v2/benchmark --compare results/my-v2-reproduction
```

Используются опубликованные маски `results/v2/masks.json` и замороженные параметры. Для воспроизведения не запускайте `--prepare`, настройку или генерацию новых масок. Каталоги `results/my-v2-reproduction` и `results/my-v2-summary` должны быть новыми; повторный запуск требует другого имени. Первый содержит предсказания, метрики, калибровочные оценки и журнал, второй — таблицы и графики. Проверка пересчитывает метрики и сравнивает численные артефакты с опубликованным запуском; время выполнения сравнивать на точное равенство бессмысленно.

V2 содержит 14 реальных рядов, объединённых в восемь групп по источнику и предметной области, и несколько временных точек оценки. Это не 14 независимых систем. Протокол и оговорки — в [v2/PROTOCOL.md](v2/PROTOCOL.md), выводы — в [отчёте v2](v2/RESEARCH_REPORT.md). Получение итоговых таблиц из уже сохранённого запуска не повторяет обучение; для полного воспроизведения нужна первая команда эксперимента.

Первый эксперимент остаётся отдельно воспроизводимым:

```powershell
.\.venv\Scripts\python.exe scripts/run_experiments.py --config configs/benchmark.json --output results/reproduction
.\.venv\Scripts\python.exe scripts/plot_results.py --input results/reproduction
.\.venv\Scripts\python.exe scripts/summarize_results.py --input results/reproduction
```

Оригинальные измерения v1 сохранены в `results/benchmark`. На облачной Linux-машине именно эксперимент v1 занял около 100 секунд и 259 МиБ пиковой памяти процесса; эти числа не описывают v2 или ваш ноутбук.

Упрощённый способ с установленным `uv` одинаков для Linux и Windows:

```powershell
uv sync --frozen
uv run gaplens repair --reference examples/reference.csv --input examples/with_gaps.csv --output my-repair --require-complete
uv run python -m pytest -q
```

## Свои данные

Нужны два CSV с колонками `timestamp,value`:

1. `history.csv`: более ранняя история; последние 25% используются для калибровки.
2. `incomplete.csv`: строго более поздний ряд; пропуски обозначены пустыми ячейками `value`.

Время должно возрастать без дубликатов, шаг и сетка времени должны совпадать. Смещения часового пояса переводятся в UTC; время без смещения считается UTC. Для отсутствующих временных меток заранее вставьте строки с пустым значением. Программа не сортирует, не удаляет выбросы и не меняет шаг автоматически. Дубли имён колонок отклоняются. Неподходящий контекст или недостаточная опора модели/калибровки приводят к сохранённому отказу; некорректный файл, пересекающаяся история или слишком короткий исходный reference — к ошибке проверки входа.

```powershell
.\.venv\Scripts\gaplens.exe repair --reference history.csv --input incomplete.csv --output own-result --method analog --neighbors 12 --context 6 --max-gap 48 --alpha 0.1
```

Длина пропуска и контекст измеряются в отсчётах. `--method linear` и `--method extra-trees` запускают базовые методы. Дополнительный `--method diverse --neighbors 4` выбирает исторические окна без взаимного перекрытия; это известный приём отбора, а не доказанная научная новизна или независимость соседей. По результатам настройки на прежних трёх рядах его целевой показатель ошибки оказался на 3,994% хуже v1, поэтому по умолчанию сохранён `analog`. Эти данные настройки не являются новой финальной оценкой.

Сезонный, Kalman/RTS и PCA-методы, а также сравнение статической и скользящей калибровки доступны в исследовательском сценарии v2; это не дополнительные варианты `gaplens repair`. Все продуктовые параметры доступны через `--help`. Код 0 означает успешный экспорт, который без `--require-complete` может содержать отказы; код 2 — ошибку проверки или выполнения; код 3 с `--require-complete` — сохранённый частичный результат.

## Повторный запуск и происхождение значений

`repaired.csv` — результат анализа, а не новый файл измерений. V2 явно отклоняет его и как `--input`, и как `--reference`, чтобы прежние оценки не становились наблюдениями, обучающими целями или калибровочной истиной. Отклоняются колонки `original_value`, `status`, `lower`, `upper`, `gap_id`. Не удаляйте их для обхода проверки: происхождение потерянных данных нельзя восстановить догадкой. Если появился новый пропуск, внесите его в копию исходного файла измерений и выполните восстановление заново.

Проверка этого контракта после первого запуска намеренно заканчивается кодом 2:

```powershell
.\.venv\Scripts\gaplens.exe repair --reference examples/reference.csv --input my-repair/repaired.csv --output rejected-reimport
$LASTEXITCODE
```

Должны появиться понятное сообщение о неподдерживаемом экспорте и число `2`; исходный отчёт сохраняется. Каталог результата не создаётся. Аналогично отклоняется экспорт, в котором после восстановления добавили ещё один пропуск.

`--overwrite` предварительно проверяет все три пути экспорта: если один занят каталогом, прежние файлы не заменяются частично. Запись остаётся отдельной заменой каждого файла, а не транзакцией на случай аварии диска. Если все пропуски непригодны или пропусков нет, модель не обучается без необходимости. Короткий сценарий с граничным отказом приведён в [LEARNING_GUIDE.md](LEARNING_GUIDE.md).

## Результаты и ограничения

В исходном эксперименте v1 AnalogBridge снизил нормированную MAE на 51,8% относительно линейной интерполяции и на 14,4% относительно ExtraTrees. Это результат на трёх выбранных реальных рядах с искусственными масками; теперь они считаются данными разработки. Полная гипотеза v1 не подтвердилась: интервалы оказались шире, чем ожидалось, и не достигли целевых 90% покрытия; для NYC покрытие целого пропуска — лишь 78,7%. Эти числа нельзя переносить на новые данные или выдавать за сравнение v1 и v2. Итог v2 следует брать из [отдельного отчёта](v2/RESEARCH_REPORT.md), включая проигрыши, отказы и статус гипотез.

Архитектура и численное ядро описаны в [ARCHITECTURE.md](ARCHITECTURE.md); демонстрационный сценарий и разбор алгоритма — в [LEARNING_GUIDE.md](LEARNING_GUIDE.md). Текущий статус проекта — исследовательский инструмент и технический отчёт. Промышленная эксплуатация и полезность в реальном рабочем процессе пока не оценивались.
